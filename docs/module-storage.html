storage

Persistence of the notebook (notes and folders), and backup/restore as a JSON file.

Where is the data? (since 2.1)

In IndexedDB (see db): one record per note and per folder. Up to 2.0, the whole notebook was a single JSON string in localStorage, which had two limits:

  • size: about 5 MB per site for localStorage, versus hundreds of MB for IndexedDB;
  • cost: every keystroke rewrote the whole notebook. Now only the changed note is written.

The metadata (chosen display, selected folder, last backup date…) stay in localStorage: they are tiny, and reading them synchronously is handy.

Migration from localStorage

On the first launch of 2.1, loadAll copies the notes and folders from localStorage to IndexedDB, in a single transaction (all or nothing), then records storage: 'idb' in the metadata. The copy only happens if the IndexedDB database is empty: data already there is never overwritten by the old copy.

The old copy is not erased: it stays as a safety net (frozen at the migration date). Golden rule: never move and delete data in the same operation.

If IndexedDB is unavailable (very old browser, storage blocked), the app keeps going with localStorage, as before 2.1.

Write strategy

  • Debounce: each change schedules a write 150 ms later; close keystrokes trigger only one.
  • "Dirty" notes: scheduleSave receives the id of the changed note; only those notes are written.
  • Comparison: flushSave compares each note to its last written version (its JSON form) and writes only the differences, deletions included. It is a safety net: after a bulk operation (import, folder deletion…), nothing can be forgotten, even if the caller does not know which notes changed.
  • Flush on visibilitychange (see main): Android may kill an app in the background without warning; so everything is written right away, in strict mode (the browser waits until it is on disk).
  • navigator.storage.persist() asks the browser not to evict the data when disk space runs low.

Writes are asynchronous and their errors (quota exceeded…) do not block the app: a note that was not written stays "different" and will be retried on the next write.

(static) importFile(notes, text, foldersopt) → {ImportResult}

Description:

  • Imports a file into the notebook: shared note (.inkline) or full backup.

    • Shared note: it is added with new ids, never overwriting an existing note (receiving the same note twice creates two copies, on purpose: we cannot know which one to keep).
    • Backup: merged by id, the most recent version (updated) wins. Importing the same backup twice has no effect. Folders of a v2 backup missing from the notebook are added; those already there (same id) are kept as they are. A v1 backup (no folders) stays readable.

    In both cases, everything goes through sanitize.
