layout

Layout engine of a staff: decides where each item goes (line and x), where barlines fall, and where the add zone is.

It is a pure function: same input, same output, no DOM. The SVG renderer (render-staff) and hit testing (the user's tap, in ui/staff/input) both call layout with the same parameters: they are therefore consistent by construction.

Algorithm

  1. Intrinsic widths: each item gets a base width from its duration (proportional engraving: a whole note takes more room than an eighth), plus room for an accidental, a dot or a long chord symbol.
  2. Measures: split by segmentMeasures.
  3. Line breaking, greedy (first-fit) algorithm: a measure goes on the current line if it fits, otherwise it opens a new line. A measure is never split in two.
  4. Justification: each line is stretched by a factor sc = availableWidth / usedWidth, capped at 2.4 to avoid an absurd stretch. The last line is not stretched, unless the pattern ends with a final barline and the line is already more than 50% full. An overfull line (measure wider than the screen) is compressed (sc < 1).
  5. Final positions of items, barlines and start repeats.

Vertical reference

Each line (system) takes a band of fixed height SH; the y coordinates inside it are given by geom.
